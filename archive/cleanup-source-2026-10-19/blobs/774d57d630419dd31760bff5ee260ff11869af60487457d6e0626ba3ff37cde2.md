# NPCDex · Version 2

Open **npcdex.html** in a modern browser. It works offline and contains its original content dataset. The accompanying Markdown documents are linked from Data → Content & saving.

## Navigation

- Select a town in the Maps tray to show all its characters and elements, grouped by area. Select a location to narrow the groups. Buildings with multiple floors show separate floor headers.
- Select a character tile to view that character’s conversations and linked shared scenes. Shared scenes also have their own tiles. A shared scene is stored once and can be reached from every participant’s character pane.
- Choose a story stage on the bottom timeline. Dots indicate dialogue conditions documented at that stage; the condition selector exposes all matching interactions. Other conditions holds entries without an established A–J story placement.
- Use Previous / Next to read individual dialogue boxes. Sequence overview displays the whole selected sequence and lets you jump to a box. Narrative notes identify choices, alternative responses, gender variants, and actions. The interface does not simulate every ROM flag or imply that alternative branches all occur in one playthrough.
- The master Male / Female selector applies to the entire engine. Your friend is Lyra for a male player and Ethan for a female player. Explicit variant metadata filters dialogue and supports gender-specific characters/elements in future content.

## Images, flags, and notes

Hover a tile or focus it with the keyboard to reveal its settings cog. Cogs remain visible on touch layouts. Settings supports a flag, a note, and an image. Area/floor headers also have settings.

Choose a PNG, JPEG, WebP, or GIF file, or enter a direct image URL and click **Download & embed image**. URL images are fetched immediately with browser credentials omitted and embedded as data URLs. A host that blocks browser downloads requires a file upload. Saved images are rendered from their embedded bytes and do not depend on the original URL. The source URL is retained as provenance. Images are limited to 10 MB each.

Dialogue entries have their own Flag entry and Add note controls. Condition notes applies to the whole selected access condition. Notes follow stable block/page keys; shared-scene annotations remain consistent from all participating characters. Changing a dialogue page or selection preserves a typed entry note in pending edits.

Each entry also has **✓ VERIFIED** and **✕ INACCESSIBLE** tester checkboxes. They are mutually exclusive; clear both to return to Unreviewed. These are tester assertions, separate from the research’s evidence and uncertainty labels. They are stored per dialogue entry, shown in Sequence overview and Flags & notes, and included in Save changes exports. A shared scene shows the same tester status from every participant’s pane.

**Flags & notes** lists all annotations and opens their recorded context. Notes are editorial metadata; original dialogue text is preserved.

## Save changes and agent handoff

**Apply changes** applies tile settings to the pending in-memory dataset. **Save changes** commits the entire current snapshot to browser IndexedDB, then downloads **npcdex-agent-export.json**. This export contains:

- All maps, locations, areas, characters, dialogue, scene links, and source IDs.
- Flags and notes with navigation context and dialogue conditions.
- Tester status for marked dialogue entries (`testStatus`: `verified`, `inaccessible`, or `unreviewed`).
- Complete embedded image data, including downloaded URL images.
- The player-gender preference, revision, and saved timestamp.

Give that exported JSON to the agent for future updates. Browser storage is specific to the browser/profile/origin and can be cleared; keep the export as your portable backup. The browser may request permission for downloads. A failed local commit is reported and does not clear the pending-change indicator.

The shipped **npcdex-data.json** is the initial editable dataset. Import a version 2 dataset using Data → Import. It becomes pending changes; Save changes commits and exports it. Importing while edits are pending asks before replacing them.

## Extending the data model

Use `version: 2`. `towns` contains top-level locations. Each town contains:

- `locations`: Tier 2 tiles with `id`, `name`, and `areaIds`. A multi-floor building points to several areas.
- `areas`: containers with `id`, `name`, `code`, optional `floor`, and canonical `elements`.
- `characters`: NPC records with `id`, `name`, `elementIds` for their direct interactions, and `sceneIds` for shared scenes. Link every participant to the same scene ID. `nameByGender` may provide male/female labels.

Canonical elements contain `points`, each with `condition`, `stages`, `ids`, `evidence`, and ordered `blocks`. A block has a stable `id`, `type: "dialogue" | "note"`, `text`, and `gender: "male" | "female" | "both"`. `gender` also works on characters, elements, and points. Do not rely on display-name replacements for new content: record the complete exact variants and gender metadata.

Use `stages: ["all"]` for explicitly constant dialogue and `stages: []` for timing that remains unknown or depends on separate conditions. Keep `uncertain: true` where appropriate. Set `kind: "scene"` on shared scenes.

Names, dialogue, and notes are escaped as text. Tile images must be embedded raster data URLs; imports cannot insert arbitrary HTML or externally referenced display images. IDs must be stable and unique within their relevant collections, with canonical element/point/block IDs unique across a town.

Annotations are keyed by entity type and ID, such as `character:actor-elm`, `point:61-5-0`, and `entry:61-5-0-block-0:0`. Annotations have `flag`, `note`, optional `testStatus`, and `context`. A missing `testStatus` means Unreviewed. Preserve block IDs and page boundaries if you need existing entry notes and tester statuses to continue targeting the same text after a content update. Reconcile affected annotations when changing those boundaries.

Embed an edited dataset into the standalone HTML with:

```sh
node update-npcdex.cjs npcdex-data.json npcdex.html
```

Validate the complete dataset through browser Import first. Existing browser-saved content takes priority over the bundled initial dataset; import the updated JSON there to review the new content.

## Research qualifications

The export retains `sourceBaseline`, an untouched copy of the original version 1 JSON, and `provenance`. Existing event IDs, dialogue IDs, canonical element/point IDs, and technical script references are retained. Character links, block IDs, gender metadata, images, and annotations are added for the new interface. Compare updated records against the baseline by their stable IDs when reconciling future changes; do not renumber original records.

The supplied dialogue guide establishes readable dialogue and the A–J journey. The content map supplies technical trigger conditions and reference IDs. Late event order, some identities, and some gender assignments remain inferred or unresolved in the research. Those source qualifications remain visible. Blank lines in the guide combine both text-box and scroll breaks, so the page navigation represents documented breaks rather than asserting their exact ROM rendering type.

Document instructions concerning OLD/NEW record edits were treated as reference conventions, not instructions to modify the game.
