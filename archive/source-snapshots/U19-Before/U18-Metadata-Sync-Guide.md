# ROMDex Metadata Cloud Sync

ROMDex 0.5.6 shares tile images, manual sibling ordering and saved parent statuses through the existing private ROMDex-Data repository. It uses your remembered cloud credential. YouTrack continues to own ticket content, attachments, priority, complexity, actual State and parent links. Selection, expanded tiles, filters and pane sizes remain local to each computer.

Metadata changes are committed to a local SQLite journal before their compatibility copy is acknowledged. Auto-Sync delivers queued changes and discovers incoming versions; Save Changes runs a single cycle when Auto-Sync is Off. Closing to the tray preserves normal synchronization. Offline edits, interrupted sends and restart retain their original operation identities and observed bases. Existing sparse ranks remain unchanged when their visible order already matches.

Independent image/status entries and orders under different parents can merge. A sibling list is one ordered operation. Overlapping or invalid changes preserve the complete versions for review. Save Changes opens Review ROMDex Metadata when needed; Connection Details also provides that entry. Choose a complete version, review its changes and confirm. Review Later and Escape preserve the draft. Newer edits invalidate an old approval. Original versions and removed image bytes remain in immutable cloud history. A chosen version supersedes an older queued parent-status assignment while preserving unrelated native edits; in-flight status requests finish before that projection is applied.

An open Work Pane dialog holds incoming metadata out of the editable view while cloud discovery continues. Applying a competing local edit therefore retains its original base and can require review. If metadata changes while an editor is opening, ROMDex asks you to reopen it against the current view. Renderer recovery releases an abandoned editor hold.

Orders are applied only to tickets currently belonging to the corresponding YouTrack parent. A stale list cannot recreate a deleted ticket, move a ticket or change a subtree. Unsaved local IDs are not published. Order capture waits while native hierarchy operations are pending. Metadata for unavailable items remains dormant for recovery.

Saved parent status is separate from inherited status. A matching inherited State written by another computer preserves the saved value. A distinct native State edit is still observed, and existing custom native State labels are retained exactly. If a native parent State equals its children’s computed rollup, those two actions cannot be distinguished from the State field alone; ROMDex preserves the saved parent value. A newly discovered saved status that would disagree with an untracked native leaf requires review rather than silently replacing it.

Current limits include 16 MiB metadata documents, 2 MiB per raster data URL, 512 KiB transport chunks, 5,000 immutable records and 256 concurrent operations for automatic merging. Unsupported formats, incomplete history, changed immutable bytes, repository/account changes and expanded access grants stop reconciliation while retaining the local copy. No destructive history cleanup, billing, Actions or LFS is enabled.

The final shared connection-light behavior and smaller workspace-toggle button remain the separately approved U19 task. Receipt publishing/reconciliation remains in later phases.
