## Preservation and compatibility

- Source-pinned older maps acquire the condition model at a managed save or the selected preparation's normalization checkpoint. The original portable document and historical artifacts remain recoverable; the service does not scan and migrate every map during startup.
- Existing record, point and block identities, source text, owner names/images, plans, notes and testing artifacts remain retained. Owner condition labels/order update the authoritative index without changing source guards. An annotation's stored testing result is not a new in-game verification of extracted access rules; existing baseline/staleness checks still apply.
- Maps without sufficient retained ROM source remain legacy references. Their old states are not silently converted into inferred access requirements. An agent-result document cannot bypass its reconciliation/testing boundary through the upgrade.
- Area exclusion prunes excluded effects; nested child areas retain their own target identities. Group extension carries the new index while retaining owner condition labels. Re-preparation preserves owner content without treating the format upgrade as a source conflict. Reviewed newer-build updates rebind condition evidence to the new source, preserve matching owner labels/condition identities and review keys, retain older unmatched content as unresolved, and still require human testing.
- Location-preview capability is deliberately unsupported until LP02. Its binding cannot silently claim previews that this reader cannot interpret. LP01's renderer proof remains next. Before LP02, the illustrative normalized crop contract needs an integer/rational wire representation compatible with the existing lossless integer JSON rules; this does not affect MX03's condition format or the approved crop behavior.
